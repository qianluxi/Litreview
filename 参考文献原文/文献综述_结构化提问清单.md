# 文献综述结构化提问清单（v1）

> 适用场景：已有 23 篇 PDF，用 Gemini Notebook / Anara / 支持长上下文的模型，产出一份可核查的综述底稿。
> 使用方式：**按 P0 → P12 顺序执行**，每条都是可直接复制粘贴的提问。不要跳步，跳步会让后面的提问失去事实基础。
> 核心原则：**一次只问一个字段**。一次问"总结这 23 篇"得到的必然是套话；一次问"逐篇给出相似度度量方法 + 页码"得到的是可用的数据。

## 〇、先做三件准备工作（不上传就先把库修干净）

### 现状核查（已替你做完）

26 个文件，实际是 **23 篇不同文献**：

| 情况 | 文件 | 处理 |
|---|---|---|
| 完全重复 | `Intelligent Co-Design of Shear Wall and Beam Layouts Using a Graph Neural Network.pdf` = `Xia2025_CoDesign_ShearWallBeam_GNN.pdf` | 只上传 1 份 |
| 完全重复 | `Intelligent Design of Shear Wall Layout Based on Graph Neural Networks.pdf` = `Zhao2023_ShearWall_GNN.pdf` | 只上传 1 份 |
| 同一篇不同版本 | `Gu2024_ShearWall_Diffusion.pdf` 与 `Intelligent-design-of-shear-wall-layout-_2024_...pdf` 均为 Gu et al., *CACAIE* 2024, DOI 10.1111/mice.13236 | 保留期刊排版版，删网页打印版 |
| **无文字层** | `WangHoward1991_IntegratedCBR_StructuralDesign.pdf`（130 页，纯扫描） | **必须先 OCR**，否则任何工具都读不出内容 |

### P0 上传前的两条硬规则

1. **命名统一**：`作者年份_关键词.pdf`，例如 `Zhao2023_ShearWall_GNN.pdf`。工具生成的引用经常带文件名，命名混乱会污染成稿。
2. **容量核算**：去重后 23 篇，Gemini Notebook 免费版单笔记本 50 个来源，**余量充足**。因此不要拆成两个笔记本——一拆就失去跨全部文献的一次性比较能力。

## 一、通用提问规则（写在每条提问前面的"系统约束"）

第一次对话时先发这一段，后续每条提问都自动继承：

```
本次对话只使用本笔记本中已上传的来源。规则：

1. 每个论断句末标注来源编号与页码，格式：[文献序号, p.X]。
2. 如果来源中没有直接依据，写"来源未提及"，不要用常识补全，不要引入未上传的文献。
3. 不确定时给出 2–3 个候选答案并说明各自的证据强度，不要选一个最像的。
4. 区分"作者原话"与"你的归纳"：归纳放在"推断"标记之后。
5. 遇到两篇文献结论冲突，必须同时列出，不要折中。
```

## 二、第一阶段：单篇画像（不要跳过）

### P1 逐篇结构化卡片

> 目的：把"读过"变成"可比对的字段"。这是整份综述唯一不可外包的一步。

```
对本笔记本中的每一篇文献，按以下字段输出一张卡片，每字段后附页码：

1. 一句话主张（作者认为自己的贡献是什么，用原文措辞）
2. 问题域（建筑设计 / 结构方案 / 通用方法）
3. 案例或数据的表示形式（符号特征 / 向量 / 图像 / 图 / 规则 / 本体）
4. 相似性或检索机制（若有：距离度量、图匹配、子图同构、嵌入、生成模型）
5. 系统形态（可运行原型 / 理论框架 / 综述 / 纯算法验证）
6. 评价方式（数据集规模、指标名称、是否有工程或人工标注的真值）
7. 明确写出的局限

要求：先输出一张总表，再逐篇给卡片。字段缺失写"未涉及"，不要留空。
```

**验收**：23 张卡片，至少 20 张的"评价方式"字段里出现了具体指标名（如 mAP、Precision@k、层间位移角、用钢量）。

## 三、第二阶段：证据矩阵（综述的骨架）

### P2 主矩阵（可直接导成 Excel）

```
把上述字段整理成一张表，列为：
文献 | 年份 | 问题域 | 表示形式 | 检索/生成机制 | 数据规模 | 评价指标 | 主要结论 | 局限

按"表示形式"分组，组内按年份升序。表内只放来源中能查到的事实，不要合并同义表述。
```

> Gemini Notebook 里用"数据表格"生成，导出到 Sheets；Anara 里用自定义 View。

### P3 相似度度量专项表（这批文献最关键的一张表）

```
只针对涉及"相似性度量"的文献，输出下表：

文献 | 度量对象（整体图像/房间拓扑/构件布置/结构性能） | 度量方法 | 是否需要学习 | 是否可解释 | 计算代价 | 失败情形（作者自述或实验结果）

再补一列"度量结果的下游用途"：仅检索排序 / 供案例改写 / 作为生成模型的奖励或校验。
```

**为什么这张表重要**：你这批文献的真实分野不在"用不用 AI"，而在**"相似"被定义成什么**——视觉相似、拓扑相似、还是可改造性相似。Borner1993 的核心主张（检索应保证"可适应"而非仅"相像"）正好是这条线的原点，让它和 vanEngelenburg2023 的图编辑距离、de las Heras2014 的游程直方图并排放，矛盾立刻可见。

### P4 评价口径对照表

```
列出每篇文献使用的数据集与指标，并回答：
(a) 哪些文献之间可以直接比较结果？给出判断依据（同一数据集 + 同一指标）。
(b) 哪些文献虽然做同一任务，但因为数据集或指标不同而无法比较？
(c) 是否存在"自建数据集 + 自定指标"的情况？列出具体文献。
```

**验收**：能明确回答"这 23 篇里真正可横向对比的只有 N 组"，这个数字本身就是综述里极有分量的一句话。

## 四、第三阶段：流派与谱系

### P5 范式聚类（不要让它自由发挥，先给假设再让它证伪）

```
假设本领域可分三条范式：
A. 符号主义与 CBR：以规则、特征、案例库为核心，强调可解释与可复用；
B. 几何/图匹配检索：以形状描述子、图同构、图编辑距离为核心，强调结构相似性；
C. 学习式生成：以 GNN、扩散模型为核心，直接生成布置方案。

请判断这个三分法是否成立：
- 哪些文献无法归入任何一类？为什么？
- 是否存在跨范式的过渡文献（例如用神经网络替代 CBR 的检索环节）？指出并给页码。
- 如果三分法不成立，提出一个更贴合来源的分类，并说明你的依据。
```

### P6 时间线与承继关系

```
按年份列出文献，并标注它们之间的显式引用关系（A 引用 B 的证据为 A 文中出现 B）。输出：
年份 | 文献 | 引用了本库中哪些文献 | 被本库中哪些文献引用

然后回答：本库中哪一篇处于"被引最多"的位置？哪一篇是孤立节点（既不引本库、也不被本库引）？孤立节点说明了什么？
```

> 说明：Gemini Notebook 对"引用关系"的抽取不一定可靠，这一条务必用 P11 核验；若错误率高，改用 Zotero 的"被引/引用"字段或 ResearchRabbit 复核。

## 五、第四阶段：冲突与局限（综述的价值所在）

### P7 矛盾清单

```
找出本库中明确互相矛盾的论断，逐条列出：
论断 X | 支持方（文献+页码） | 反对方（文献+页码） | 分歧的实质（定义不同 / 数据不同 / 评价指标不同 / 假设不同）

至少给出 5 条。若不足 5 条，说明本库在哪些方面证据过于一致，以及这种一致性可能是真实的还是样本偏差造成的。
```

**预期会浮现的三组冲突**（可用来检验工具是否真的读进去了）：
1. 生成式方法（Zhao2023、Gu2024、Xia2025）主张"省去检索、直接生成"，而 CBR 路线（Aamodt1994、Maher1996）主张"复用优于生成"——这实质是**知识与参数之争**。
2. 图像表示 vs 图表示：Gu2024 用图/掩码张量处理"绘制表示复杂"，Zhao2023 明确批评像素方法参数多、无法反映拓扑；但 vanEngelenburg2023 主张**不学习**的图编辑距离即可媲美深度度量学习——对"必须上深度模型"构成反例。
3. 评价口径：建筑平面检索类（Ahmed2013、de las Heras2014、Rodrigues2017）用检索指标；结构生成类（Zhao2023、Gu2024）用工程性能指标（层间位移角、用钢量）。**两套指标之间没有换算关系**，这是本领域最容易被掩盖的方法论断层。

### P8 未解决的问题

```
汇总所有文献"明确写出的局限"与"未来工作"，去重后按出现频次排序，输出：
问题 | 提出者（文献+页码） | 被提及次数 | 是否已有文献部分解决（指出是哪篇）

排除掉"数据量不足""泛化性待验证"这类通用套话，只保留领域特有问题。
```

## 六、第五阶段：定位与研究空白

### P9 空白论证（要它反驳你，不要它捧你）

```
基于以上矩阵与冲突清单，回答三个问题：

1. 若一项研究要做"给定结构方案的相似性检索 + 可复用性判断"，现有文献留下的具体缺口是什么？请给出缺口 → 依据文献 → 页码的链条，不要给笼统的"缺乏系统性研究"。
2. 对每个缺口，找出本库中最接近的已有工作，说明它为什么还不够。若某个缺口其实已被解决，请直接说"该缺口不成立"。
3. 列出 2 个"看起来是缺口、实际不是"的伪缺口，并说明理由。
```

**验收**：第 2 问必须出现至少一次"该缺口不成立"。如果三条缺口全部成立、毫无反驳，说明它在顺着你说，重跑 P9 并加一句"请以审稿人立场逐条攻击这三个缺口"。

### 常用纠错话术

- 页码不对：`第 3 条页码有误，重新给出来源中确切的页码与原文片段，找不到就说找不到。`
- 掺入外部知识：`这句话在本库来源中无依据，删除；若确有依据，给出文献与页码。`
- 回答变空泛：`上一轮回答过于概括。改为逐篇给出，每篇不超过 3 句，必须包含具体方法名或数字。`
- 额度将尽时：`接下来只回答一个问题，不要生成报告或表格，不要使用 Deep Research。`

- [ ] 每篇被引文献的年份、作者姓，与 PDF 首页一致
