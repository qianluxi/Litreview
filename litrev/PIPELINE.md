# 文献综述流水线（生成 → 校验 → 回灌）

这条链解决的是此前反复出现的同一个问题：**生成方每次都能"完成"，但没人能判断哪一句是原文、哪一页是编的。**
所以这里不做"更好的提示词"，只做三件可机械判定的事，并把失败变成可回灌的清单。

## 零、怎么启动（Windows）

双击 `litrev.bat` 进菜单；把 `.md` / `.xlsx` 拖到它上面可直接跑对应校验。

| 入口 | 行为 |
|---|---|
| 双击 | 菜单，1–6 选项 |
| 拖 `.md` | 直接核验引文，同时出 xlsx 报告 |
| 拖 `.xlsx` | 直接校验矩阵（子集表请走菜单第 4 项） |
| `litrev.bat 1..6` | 不进菜单，跑完即退出，便于挂到别的批处理里 |

菜单键与命令的对应：

| 键 | 等价命令 |
|---|---|
| 1 | `python litrev.py index` |
| 2 | `python litrev.py verify ../notes/文献综述_初稿_v1.md --xlsx` |
| 3 | `python litrev.py matrix ../notes/文献对比与系统特征表2.xlsx` |
| 4 | `python litrev.py matrix ../notes/P3_度量汇总_补全版.xlsx --allow-subset` |
| 5 | `python litrev.py locate "…"` |
| 6 | 打开本文件 |

脚本会自己找 `python`（找不到退回 `py -3`），并检查 `pymupdf` / `openpyxl`，缺了就 `pip install`。

> 维护提醒：`litrev.bat` **必须保存为 GBK/ANSI 编码**。存成 UTF-8 时，cmd 会按当前代码页把中文字节拆断，出现"‘xlsx"’不是内部或外部命令"这类整行崩坏（已实测）。

## 一、三个完成条件（必须机器可判）

| # | 条件 | 判定方式 | 不满足的后果 |
|---|---|---|---|
| C1 | 引号内的句子在原文中**逐字存在** | 去空白/连字符/连字后做子串匹配 | 引号不成立，属"改写当直引" |
| C2 | 标注页码 = 该句**实际所在页** | 命中页比对 | 读者按此检索查不到 |
| C3 | 标注作者 = 该句**实际出自的文件** | 文件名/别名比对 | 张冠李戴 |
| C4 | 论断被引文支撑（2026-11-09 新增） | 审计层判 `SUPPORTED`，或人确认 | 引文真实但答非所问 / 略超原文 |

> C1–C3 是机械可判的，C4 是**半自动**：审计员判 `SUPPORTED` 可直接通过，判非 `SUPPORTED` 必须人看一遍（见第八节）。

外加两条结构条件：矩阵**行数 = 文献数**、每篇文献**只占一行**。

C1–C3 全部通过之前，任何"综述已完成"的说法都不成立。这就是 loop 的终止条件。

## 二、四个步骤

```
0 建索引  →  1 生成（模型/人）  →  2 校验（本工具）  →  3 回灌差异  →  回到 1
                                      ↓ 全部 PASS
                                   交付
```

### 0 建索引（文献变动时才需重跑）

```bash
cd papers/litrev
python litrev.py index
```

产出 `_index/corpus.json.gz`（页级检索键）与 `_index/manifest.csv`（页数、印张偏移、扫描件、重复件、文字层词/行）。
索引会自己识别四类麻烦：**无文字层**（必须 OCR）、**内容重复**（网页版/期刊版）、**印张页码偏移**、
**逐词断行**（词/行 < 3，按行取句必得碎片）。

### 0.5 导出正文（交抽取工之前）

```bash
python litrev.py text                 # 全部 PDF → _probe/texts/<文献>.txt（带 <<<PAGE n>>>）
python litrev.py text --dry-run       # 只报健康度：raw → layout 的词/行变化
python litrev.py text --only <文件名主干> --raw   # 退回 page.get_text()，仅在对照时用
```

为什么不是直接 `page.get_text()`：有些 PDF 把每个词、甚至半个词登记成独立「行」（`Borner1993` 实测 1.03 词/行），
逐页直出后按行取句只能得到碎片。`text` 用词级坐标重建阅读顺序（block 内按 y 聚行、block 间 XY-cut 分栏），
同一篇能回到 7.60 词/行。索引里同时保留 raw 键与版面键，换语料不会推翻已有判定。

### 1 生成

在 Notebook / Claude / 任意模型里生成，但输出必须满足格式约定（见第四节模板）。
**关键约束：页码一律用 PDF 物理页**，与正文文首的"页码约定"一致；换期刊页码是最后一步的事。

### 2 校验

```bash
python litrev.py verify ../notes/文献综述_初稿_v1.md --xlsx
```

输出：终端表 + `_引文核验.md`（含待改清单）+ `_引文核验.xlsx`（红/黄标）。
退出码 0 = 全部通过，1 = 有待改项。

矩阵另跑：

```bash
python litrev.py matrix ../notes/文献对比与系统特征表2.xlsx
python litrev.py matrix ../notes/P3_度量汇总_补全版.xlsx --allow-subset
```

### 3 回灌

把报告里的"待改清单"整段贴回生成方，而不是笼统说"再改改"。
每条都是「现文 / 原文 / 位置」三件套，模型无法含糊过去。

## 三、判定码

| 码 | 含义 | 处理 |
|---|---|---|
| `PASS` | 逐字存在、页码正确、作者匹配 | 无需动作 |
| `PAGE` | 逐字存在但页码错 | 改成报告给出的实际页 |
| `AUTHOR` | 逐字存在但出处不是所标作者 | 核对该句真实出处，防张冠李戴 |
| `PARAPHRASE` | 引号内句子与原文有出入 | 改回原句，或删引号改转述 |
| `MISSING` | 全库找不到 | 删引号，或回原 PDF 确认 |
| `NOPAGE` | 引文存在但未标页码 | 补页 |
| `ZHQUOTE` | 中文引号内的长段（译引） | 补原文英文句与页码，否则改转述 |

## 四、生成方提示词模板（粘贴到 Notebook / 对话框）

```
写作规则（违反任一条，稿件将被程序判为不合格）：

1. 直接引用必须逐字抄录原文，不得改词、不得拼接两句、不得省略中间部分。
   原文的 robustly / holistically / suitable to 这类词必须原样保留。
2. 每条直接引用后紧跟标注，格式固定：（作者, 年份, p.PDF页）。
   页码用 PDF 物理页，从 1 开始计数，不是期刊印张页码。
3. 无法确认原文措辞时，不要加引号，改为不带引号的转述。
4. 不得引用未上传的文献；需要背景知识时明确写"（背景，非本库文献）"。
5. 一章内的直接引用不超过 8 条；引用密度越高，逐字准确性越差。
```

## 五、边界（这条要说清）

这条链**只能验证事实层**：句子是否逐字、页码是否对、出处是否张冠李戴。

它无法验证判断层：
- 这个研究缺口是否真的成立
- 这条论证主线是否站得住
- 两个流派的划分是否合理

所以流程的终点不是"程序通过"，而是"程序通过 + 你看过判断层"。P7 那次核出 3 处错引之后，G3 留不留仍然只能由人决定——同一件事。

## 七、常用命令

```bash
python litrev.py index                                  # 建/重建索引
python litrev.py locate "text"                          # 一句话回查出处与页码
python litrev.py verify 稿件.md --xlsx                   # 核验引文
python litrev.py verify 稿件.md --only Zhao2023_ShearWall_GNN.pdf   # 只查某篇
python litrev.py matrix 表.xlsx                          # 校验全覆盖矩阵
python litrev.py matrix 表.xlsx --allow-subset           # 校验子集表
python litrev.py matrix 表.xlsx --sheet 证据矩阵_v2 --col 2
```

## 八、论断层审计（2026-11-09 新增）

`verify` 守 C1–C3（字符串层），审计员守 C4（语义层）。两者不是替代关系：一条引文可以 `PASS` 却判 `PARTIAL`——上一轮那 4 条就是这样，`verify` 4/4 通过，一条都没回答问题。

**怎么跑**：主控把 `(id, 论断, 引文, 页码, 出处)` 五元组按批交给 `auditor-<批次>`（每个批次一个 agent，只能读本批输入、只能写本批输出），它只输出判定表，不改稿。判定标准是 `_probe/AUDIT_CONTRACT.md`，不要临时改口径。

| 码 | 含义 | 处理 |
|---|---|---|
| `SUPPORTED` | 论断每个成分都能在引文里找到依据 | 可直接通过 |
| `PARTIAL` | 方向对，但限定被加强 / 范围被放大 | 人看：改论断或换引文 |
| `UNSUPPORTED` | 方向相反、无关，或对象被换掉 | 人看：这条不能引 |
| `DEPENDENT`（自足轴） | 引文主语落在引号外 | 扩引文范围，把主语包进来 |

**三条使用纪律**（标定实测得出，别省）：

1. **只单侧自动**：`SUPPORTED` 可自动放行；非 `SUPPORTED` 一律人看。实测严重度会偏轻——该判 `UNSUPPORTED` 的有 2/5 被判成 `PARTIAL`，拿它做自动拦截会漏。
2. **基准先写**：要复核审计员判得准不准，必须**先**把人工标签写定再跑机器，否则标定等于自证。
3. **它仍看不见断章取义**：闭卷审计只判断言与引文的关系，原文下一句就反驳的情况抓不到。这条只能靠开卷复核或人读。

标定数据：支撑轴与人工基准 11/13（两次独立派发之间 13/13 一致），变异检出 5/5，详见 `_probe/AUDIT_RESULT.md`。

### 抽检（2026-11-09 加入，机械可复现）

`SUPPORTED` 是分诊结果，不是合格证（契约 §七.2）。每轮审计后从**当前判为 SUPPORTED 的条目**里用固定种子抽 10–15%：

```bash
python tools/audit_prep.py sample            # 候选集 = 当前 8 张判定表里的 SUPPORTED
python tools/audit_prep.py sample --check    # 复算比对，确认可复现
python tools/audit_prep.py verify-sample     # 审计员回写 out_S1.md 后机械验收
```

- **不要再直接用 `litrev.py sample` 生成 S1**：那条命令从全库 131 条抽，会混入本来就要人看的 PARTIAL/UNSUPPORTED。
  本工具只读判定表与批次输入，裁判 `litrev.py` 一字不改。
- 种子与比例写进批次文件头，**同一批数据重跑必须抽出同一组条目**；答案键 `SAMPLE_S1_KEYS.md` 留在主控侧，不进派发提示词。
- 抽检出现"该判 PARTIAL 却给 SUPPORTED"→ 整批重审，不逐条修补（逐条修会把系统性偏松掩盖成偶发）；
- 新批次要在 `_probe/audit/BATCHES.json` 登记并跑 `tools/gen_subagents.py`，才会有对应的 `auditor-<批次>`（它只能读这一批、只能写这一批的输出）。完整规程见 `RUNBOOK.md` §五。
