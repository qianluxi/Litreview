# 论断层审计层：设计与标定结果

测试日期：2026-11-09
目的：补上 `litrev.py verify` 唯一没守的那一层——**引文真实、页码正确，但这句话是否撑得起那个论断**。
执行方式：WorkBuddy 主控 + 3 次并行/独立 subagent 派发（A、B、C），不是 OpenCode 原生 `task`。原生派发已由本轮新加的 `auditor` 角色文件承载（`Litreview/.opencode/agents/auditor.md`）。

## 一、为什么单独做一层，而不是改 verify

`verify` 判的是字符串：这句在不在库内、在哪一页、署的是不是这篇。它判不了语义，改它也判不了——这是工具性质的边界，不是实现缺陷。

上一轮（`RESULT.md` 第三节）已经给出了三个它抓不到的实例：答非所问（反向测试 4/4 PASS 却零回答问题）、引文不自足（`it` 的主语在引号外）、论断略超引文（`data structure` → "标准"）。这三类的共同点是：**字符串全对，语义上有一条没跨过去**。

所以这一层不复用 `verify` 的任何逻辑，改成独立判断 + 独立标定。

## 二、设计

| 项 | 内容 |
|---|---|
| 输入 | 五元组：`id / 论断 / 引文 / 页码 / 出处`。**闭卷**——不给上下文 |
| 判定 | 两个独立轴：支撑 `SUPPORTED / PARTIAL / UNSUPPORTED`，自足 `SELF / DEPENDENT` |
| 契约 | `_probe/AUDIT_CONTRACT.md`（码定义 + 五条易错规则 + 输出格式） |
| 输出 | 固定表格，每行必须给出"引文里的依据"（≤15 字，必须是引文原词） |
| 标定集 | `_probe/audit/CASES_v1.md`，13 条，全部来自已 PASS 的笔记 |
| 基准 | `_probe/audit/LABELS_v1.md`，**在派出审计员之前**写定 |
| 变异集 | `_probe/audit/MUTANTS_v1.md`，5 条注入变异 + 3 条原样对照，顺序打散 |
| 独立性 | A、B 两次派发内容完全相同、互不可见，B 打乱顺序；C 只看变异集 |

基准先写、机器后跑，是为了避免"看完机器判定再改答案"。这一点必须在流程上落实一次，否则标定等于自证。

## 三、结果

### 支撑轴：稳定，且偏严

| 轴 | A | B | A 与 B 之间 |
|---|---|---|---|
| 支撑 | 11/13 | 11/13 | **13/13 完全相同** |
| 自足 | 13/13 | 10/13 | 10/13 |

A、B 与基准不一致的**恰好是同两条**（02、06），且**同向**（都比我严）。两个互不可见的判断在同一处同向偏移，说明分歧来自口径（我的基准偏松），不是判断力随机波动。偏严的方向对使用者安全：误伤只会多送几条给人看，不会放行坏条目。

### 关键结果：verify 的盲区被接住了

标定集 10–13 就是上一轮"4/4 PASS 却一条都没回答问题"的那四条。A、B 全部判 `PARTIAL`，理由全部指向同一处——论断里的"没有给出 / 没有报告"是**缺席命题**，单条引文证明不了；并明确指出"变体数量有限见 p.7，不在本条"这类跨页错配。

也就是说：**同一批引文，`verify` 给 4/4 PASS，审计层给 0/4 PASS。** 这条差异就是这一层存在的理由。

### 灵敏度：能抓，但严重度会偏轻

| 指标 | 结果 |
|---|---|
| 检出率（变异条目被判为非 SUPPORTED） | **5/5 (100%)** |
| 严重度精确率（判定码与期望一致） | 3/5 |
| 对照稳定性 | 3/3 与第 1 轮一致 |

两条偏轻的都是该判 `UNSUPPORTED` 却判成 `PARTIAL`：
- R7「Semantic Fingerprint → BIM 标准」——规则 3 明确写了"对象不是同一个东西 → UNSUPPORTED"，审计员仍给 PARTIAL；
- R5「索引是唯一决定相关性的环节」——"唯一"属排他性最高级，也给了 PARTIAL。

结论很直接：**判定码可用于分诊，不可用于自动拦截。** 只有 `SUPPORTED` 能自动通过（两次误伤都在安全侧），非 SUPPORTED 一律人看。

### 自足轴：定义有歧义，已修订

B 把 `Using this formula...`、`After these steps...`、`For the actual...we use...` 判 `DEPENDENT`，理由是句首有指代；A 判 `SELF`，理由是主谓齐全。规则原文只写"指代落在引号外"，两种读法都成立。

修订为：**只管主语**。句首的指代性状语不算依赖。已写入 `AUDIT_CONTRACT.md` 第五节与 `auditor.md`。

## 四、结论

**能用，但只能当分诊器，不能当闸门。**

| 用法 | 是否成立 | 依据 |
|---|---|---|
| 自动放行 `SUPPORTED` 条目 | 成立（安全侧误伤） | A/B 与基准的分歧都是"把好的判成有问题" |
| 自动拦截非 `SUPPORTED` 条目 | **不成立** | 严重度 2/5 偏轻，会把"对象被换掉"降级成"措辞加强" |
| 替代人看论断层 | 不成立 | 闭卷，断章取义看不见 |
| 把 22 篇的复核量从 100% 降到"非 SUPPORTED 那部分" | 成立 | 13 条里非 SUPPORTED 11 条（含 4 条真问题），够用但要人过一遍 |

成本：两轮共 3 次派发、零人工干预。按这次的比例，22 篇全量大约会产生 60–80 条论断，需要人复核的是其中被判非 SUPPORTED 的部分——这就是这一层买到的压缩比。

## 五、局限（比结论更重要）

1. **一个模型**：A、B、C 都是同一模型（本会话 subagent）。三者一致只证明"同一口径下稳定"，不证明"换个模型也这样"。换模型必须重标。
2. **n 小且同源**：21 条全部来自 3 篇文献、同一批抽取方。22 篇全量时，论断的失败形态很可能不在这次覆盖内。
3. **基准单标**：只有一人标，所以 11/13 的含义是"与一个口径吻合"，不是"与真理吻合"。
4. **闭卷盲区**：断章取义（原文下一句就反驳）看不见。要补这一点只能改成开卷，把上下文喂进去，成本与噪声都会上升。
5. **只测了"引文→论断"，没测"论断→论证主线"**：这条链的最上层仍然只能由人判，`PIPELINE.md` 第五节的边界没有被这层解决。
